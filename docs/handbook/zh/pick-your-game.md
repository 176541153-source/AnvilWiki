## 为什么选品排在建站前面

游戏 wiki 的流量结构:新游戏爆发后 **2-8 周是黄金窗口**,承接该游戏生命周期 60-80% 的搜索量,此后指数衰减。窗口选对了,普通内容也有排名;选错了,写得再完美也没有流量。

选品判断的本质是两个概率的乘积:

1. 这个游戏会火吗?(需求验证)
2. 火的时候 Google 结果页还有空位吗?(竞争验证)

**硬性退出规则(防选品瘫痪症)**:评分 ≥60 就动手,竞争检查一票否决,整个选品最多花 2 天。选品不是研究项目,是抢时间窗。

## 第一步:广撒网列候选(30 分钟)

从这些来源各挑 3-5 个候选,凑够 10-20 个再进入评分:

| 来源 | 看什么 |
|---|---|
| itch.io `/newest`(Play in browser) | 每日新游,零竞争窗口最大 |
| Steam 新品/热门愿望单 | 品质信号强,但竞争也强 |
| Roblox 新游 rising | codes/wiki 需求最密集的生态 |
| YouTube 游戏频道近期爆款 | 50K+ views / 7 天 = 需求存在的金标准 |

## 第二步:信号模型评分(每个候选 5 分钟)

对每个候选按四项打分(0-100,**≥60 进入下一层**):

- **wiki 内容深度**(硬门槛,不满足直接淘汰):游戏有没有足够的机制/物品/攻略/Boss 可写?纯休闲小游戏没有 wiki 需求。
- **社交证明**:评论数/订阅/同时在线;devlog 活跃度(作者还在更新 = 内容窗口长)。
- **标题搜索友好度**:玩家会搜「游戏名 + wiki/guide/codes」吗?
- **英语内容**:面向国际搜索量(英语内容缺位既是需求信号,也是你的机会)。

## 第三步:需求验证(最关键,别跳过)

用 Google Trends 对比锚定词:`{游戏名} codes` / `{游戏名} wiki`,基准词选一个你已知流量的词。

**只有搜索量真实存在且在上升,才值得建站。** 最常见的坑:YouTube 高播放但 Trends 无搜索——观众在 YouTube 看完就走了,不搜 wiki。

**双源规则**:需求信号至少两个独立来源交叉确认(如 Trends + YouTube)。只有单一来源(如仅 Reddit 讨论)的,先观察一周再决定。

## 第四步:竞争检查(2 分钟,一票否决)

Google 搜 `{游戏名} wiki` 和 `{游戏名} codes`,看前 10 条结果:

| SERP 形态 | 结论 |
|---|---|
| 结果 < 10 条,或多为 PDF/论坛帖/YouTube | **空位,立即建** |
| Fandom 有但内容薄、更新慢 | 可切(用更完整的结构化内容竞争) |
| Fandom/Game8 内容厚且日更 | **放弃,换下一个** |

## 用 AI 加速:选品分析提示词

把原始数据喂给 AI(ZCode / Claude Code / Codex 任意工具,网页版 ChatGPT 也可),让它跑漏斗。**替换所有 `<>` 占位符后整段发送**:

```text
你是游戏 wiki 选品分析师,按四层漏斗评估:发现→评分→需求验证→竞争验证。
【素材】
游戏名:<游戏名>
Google Trends 数据:<粘贴 "{游戏名} codes/wiki" vs 基准词的对比数据>
Google 搜索前 10 结果:<粘贴 "{游戏名} wiki" 和 "{游戏名} codes" 结果列表>
其他信号:<YouTube 播放 / Roblox 在线 / 社区讨论>
【任务】
1. 评分表(0-100,≥60 通过):wiki 内容深度(硬门槛,不足直接淘汰)/社交证明/标题搜索友好度/英语内容
2. 需求验证:Trends 是否真实上升;双源规则(Trends+YouTube 等两个独立来源)是否满足
3. SERP 空位:结果<10 条或多为 PDF/论坛/YouTube=空位立即建;Fandom 厚且日更=放弃
4. 结论:建 / 可切 / 放弃 / 观察一周,附一段理由
只分析,不写任何文件。
```

这是**分析类提示词**:不写文件,所以不内嵌构建验证条款,改为约束输出格式(评分表 + 明确结论)。

## 产出首日 10 页清单

选品通过后,立刻让 AI 把结论转成首日 10 页规划:

```text
基于选品结论规划首日 10 页。游戏名:<游戏名>;已验证搜索词:<列表>。
优先级:codes → beginner guide → 3 篇 boss 攻略 → tier list → how-to-redeem FAQ → Top3 窗口词页。
输出表格:优先级/页面/slug/category/建议标题/目标关键词/需要我提供的素材。
缺数据的页面标注"待我补充",并列清单问我。只规划,不产页。
```

产页顺序背后的逻辑(为什么 codes 第一):

| 顺序 | 页面 | 为什么 |
|---|---|---|
| 1 | `{game} codes`(codes frontmatter,自动 Active/Expired 分区) | 流量最高的页面类型,玩家默认日更 |
| 2 | beginner guide(`guides`) | "how to start X" 是新手第一搜 |
| 3-5 | 3 个最重要 Boss/关卡攻略(`bosses`,带数据卡) | 长尾明确、可引用性强 |
| 6 | tier list / 最佳装备排名 | Commercial 意图,RPM 高 |
| 7 | how to redeem / 基础机制 FAQ | 问题式 H2 → featured snippet 候选 |
| 8-10 | 选品时验证过的 Top 3 搜索词对应页面 | 窗口词优先 |

## 意图 → 页面类型决策表(产页前先分类)

| 搜索意图 | 特征词 | 页面类型 | 千万别 |
|---|---|---|---|
| Transactional | codes / redeem / free | codes 页(表格+一键复制) | 写成 3000 字指南 |
| Informational | how to / how do I | 指南页(问题式 H2) | 堆砌表格没有解释 |
| Commercial | best / tier / vs / ranking | 排名/对比页(表格为主) | 不给结论 |
| Navigational | wiki / guide / map | 聚合页/分类页 | 只放链接没有内容 |

> **✅ 验收(全部成立才算完成)**
> - 决策:有一个明确的「建 / 放弃」结论,而不是"再看看"
> - 清单:拿到一张 10 行的页面规划表,含 slug/category/目标关键词
> - ☐ 时间:从开始选品到做出决定 ≤ 2 天
> - ☐ 每个入选游戏都能说出:需求证据(哪两个来源)+ 竞争证据(SERP 形态)
